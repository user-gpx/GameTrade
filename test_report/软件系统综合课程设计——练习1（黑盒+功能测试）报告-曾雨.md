## 一、项目简介

### 1.1 项目背景

随着网络游戏产业的蓬勃发展，玩家之间对游戏内道具的交易需求日益增长。然而，现有的交易方式多为私下交易，存在欺诈风险高、交易流程不透明、资金安全无保障等问题。本系统旨在为游戏玩家提供一个安全、可靠、便捷的在线交易平台。

### 1.2 项目架构

- **技术栈**：Python Django 4.2 + Bootstrap 5 + SQLite
- **架构模式**：B/S 架构，MVC 设计模式（MTV）
- **开发工具**：VS Code
- **被测模块**：用户认证模块（users）、道具管理模块（items）

### 1.3 被测模块功能概述

**用户认证模块**：提供注册、登录、登出、个人资料查看与编辑功能，是整个平台的入口和身份管理基础。

**道具管理模块**：提供道具的浏览、搜索筛选、详情查看、发布、编辑、下架（软删除）、收藏/取消收藏功能，是平台的核心业务模块。

## 三、测试方法选择

本次测试主要采用以下黑盒测试方法：

| 测试方法 | 适用场景 | 应用功能点 |
|----------|----------|------------|
| **等价类划分法** | 输入域可划分有效/无效等价类 | U-01注册、U-02登录、I-02搜索、I-06发布 |
| **边界值分析法** | 输入有明确边界约束 | U-01密码长度、I-06价格范围、分页边界 |
| **判定表法** | 多条件组合决定不同结果 | U-02登录（用户名×密码）、I-09收藏（登录×已收藏） |
| **场景法** | 业务流程有明确步骤 | 注册→登录→编辑→登出，发布→浏览→收藏→下架 |
| **因果图法** | 多个输入条件组合产生不同输出 | I-03多条件筛选 |

## 七、体会与感想

1. **黑盒测试方法的实践价值**：通过等价类划分，能有效减少冗余测试用例；边界值分析在价格、长度等有明确范围的输入上非常有效；判定表法清晰展示了多条件组合的处理逻辑。

2. **场景法最贴近用户实际使用**：模拟完整业务流程（注册→登录→发布→购买）能发现单一功能点测试无法覆盖的集成问题。

3. **自动化脚本的价值**：Selenium 脚本能重复执行回归测试，但在元素定位（CSS Selector）和等待机制上需要较多调试。

4. **团队协作**：与组员交叉测试能发现思维盲区，提高测试覆盖率。
